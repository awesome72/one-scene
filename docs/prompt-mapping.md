# SKILL.md → 프롬프트 파일 매핑 (Phase 2)

프롬프트는 `backend/app/prompt_sync.py`가 SKILL.md를 잘라 **원문 그대로** 만든다.
SKILL.md를 고쳤으면 `cd backend && uv run python -m app.prompt_sync`. 동기화가 깨지면 테스트가 실패한다.

## 파일 구성
| 파일 | SKILL.md 출처 | 쓰임 |
|---|---|---|
| `prompts/core.md` | 0~4장, 8~10장 | 모든 단계 질문자의 공통 시스템 프롬프트 |
| `prompts/stage1_topic.md` | 5장 서론 + 1단계, 6장 | 1단계 모듈 |
| `prompts/stage2_paragraph.md` | 5장 서론 + 2단계 | 2단계 모듈 |
| `prompts/stage3_sequence.md` | 5장 서론 + 3단계, 6장 | 3단계 모듈 |
| `prompts/stage4_revise.md` | 5장 서론 + 4단계, 6장, 7장 | 4단계 모듈 |
| `data/cliches.yaml` | 7장 (+2장 강조어, 4-2 감정어) | 상투어 린터 사전 |

11장(세션 상태)은 프롬프트에 넣지 않는다. 같은 내용을 prompt_builder가 실제 상태 YAML로 넣는다.

## 가이드(12장 Phase 2 지시)와 다르게 한 부분
1. **4장 서사 아크를 단계 파일이 아니라 `core.md`에 넣었다.** 질문 품질 기준(3장)의 "서사 아크 쪽으로 한 걸음"이 모든 단계에 적용되기 때문.
2. **10장 대화 예시를 `core.md`에 넣었다.** 가이드는 0~3, 8, 9장만 지정했지만, 좋은 예와 나쁜 예가 질문 품질에 가장 직접적인 기준이다.
3. **6장 길이 기준은 1·3·4단계에만 넣었다.** 1단계(길이 결정), 3단계(단락 분량), 4단계(문장 길이)에서만 쓰인다.

## 원문에 더한 것 (원문 문장은 수정하지 않음)
- 각 파일 첫 줄: 자동 생성 안내 주석
- `core.md` 머리: "n장" 참조 안내 한 줄 — 파일을 나눈 뒤에도 "7장을 따른다" 같은 원문 참조가 어디를 가리키는지 알 수 있게

## `cliches.yaml`에서 원문과 다른 점
- 원문은 표현 목록, 사전은 **활용형까지 잡는 정규식**이다 (예: "가슴이 먹먹했다" → `가슴이 (먹먹|뭉클)`)
- 교정 질문: 7장 감정 명명 표의 질문 3개는 원문 그대로, 나머지는 4-2의 원칙("인용하고 질문으로")과 가이드 9장 예시를 따라 작성
- 2장의 강조어 "진짜·완전·너무"를 과장 항목으로 추가 (목업 초안의 "너무 지쳐 있었다"가 표시 대상)
- 각 항목에 `label`(목업 초안 화면의 종류 이름), `source`(원문 표현), `examples`(탐지 테스트용) 추가
