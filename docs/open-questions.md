## B. 데이터·엔진 (Phase 1, 3 전)

### B1. `topic_sentence`, `target_length`는 누가 채우나
- stage_machine 1단계 마감 조건이 둘을 요구하지만, extractor 출력 스키마에 없음
- 제안: 코치가 결정 질문을 던진 뒤, 사용자 답을 확정 UI(버튼)로 저장. 또는 extractor에 `topic_candidate`, `length_choice` 필드 추가
- 결정: (2026-10-09, 잠정) extractor가 사용자가 직접 말한 주제 문장(원문)과 길이 선택을 뽑아 비어 있을 때만 채운다. 사용자는 `PATCH /sessions/{id}`로 언제든 고친다

### B2. 사용자·인증
- `sessions.user_id`는 있지만 users 테이블과 인증 방식이 없음
- 제안: MVP는 users 테이블 + 이메일 매직링크(또는 베타 초대 코드). Phase 1에 최소 형태로 포함
- 결정: (2026-10-09, 잠정) users 테이블 생성. 개발 중에는 `X-User-Id` 헤더로 구분(없으면 `dev-user`). 베타 전에 실제 인증으로 교체

### B3. 정서적 안전 신호
- 기획안 12장·SKILL.md 9장: 고통 신호 감지 시 진행 중단. 그러나 7장 파이프라인에 해당 단계 없음
- 제안: extractor 출력에 `distress: bool` 추가 → true면 질문 대신 상태를 묻는 고정 응답 + 넘어가기 제안
- 결정: (2026-10-09, 잠정) 제안대로. extractor `distress` → 질문 생성 없이 `data/fixed_replies.yaml`의 고정 응답

### B4. 재료 원문 규칙과 목업의 재료 카드
- 가이드: 재료 `text`는 사용자 발화의 **연속된 부분 문자열**
- 목업 재료 카드: "회의실이었어요. 창밖만 보고 있었어요." — 실제 발화의 중간 문장이 빠진 비연속 발췌
- 제안: 규칙 유지(재료 2개로 저장), 카드에서는 같은 블록 재료를 이어 표시. 공백·따옴표 정규화 규칙은 Phase 3에서 정의
- 결정: (2026-10-09, 잠정) 규칙 유지. 공백·따옴표 차이만 허용해 찾고, 저장은 발화 쪽 원문 표기로 (`extractor.find_verbatim`)

### B5. 교정 "그대로 두기"
- 목업 초안 화면에 [그대로 두기] 버튼 → 사용자가 무시한 지적을 저장할 곳이 없음
- 제안: `drafts.lint_result` 항목에 `dismissed: true` 추가, 4단계 마감 조건에서 제외
- 결정: (2026-10-09, 잠정) 제안대로. `drafts.lint_result` 항목에 `dismissed` 저장 (Phase 6에서 구현)
